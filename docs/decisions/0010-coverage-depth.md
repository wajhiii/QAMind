# 0010: Coverage depth: browsers, screens, speed, messages, tickets

Status: accepted (Phase 7.9). Date: 2026-11-03.

## The shape: deterministic tools the agent calls, leads it verifies

The agent's own browser is the host's browser tool: one engine, one window. Other engines and screen sizes, pictures compared pixel by pixel, timings and a mail inbox are exact work, so each is a QAMind command (`sweep`, `baseline`, `perf`, `mail`/`sms`, `ticket`) that prints JSON the agent reads. **Every result is a lead, not a verdict**: it is repeated twice and written as a finding like anything else. Nothing new is a dependency: pictures are read and written by a small PNG codec in the repository, MIME by a small reader.

- **One engine for the browser checks.** The bank's UI runner and the page sweep share `core/lib/browsers.ts` (finding Playwright, launching an engine, the request policy) and `core/lib/bank/uisteps.ts` (the step vocabulary). The policy, including the check of every redirect, is therefore the same code in both.
- **The sweep reuses the page audit** the agent already runs by hand (`page-audit.js`), so its leads mean the same thing, and adds the things a person sees: text that was never filled in, console errors, failed requests, how long the page took. Pages and sign-ins come from a file the agent writes (`data/sweep-pages.json`), validated against the config like every other agent-written file: only the config's web UIs and roles, only a role's own login variables, paths not addresses. `data/pages.json` was taken (the product map), so the name is different.
- **Grouping is by where a problem happens**: the same problem in four browser/size combinations is one group that says "only at mobile" or "only in webkit". The finding's own `browser` and `viewport` fields carry it into both reports.
- **A browser that cannot start is Not tested, and `report lint` makes it so** (an error, not a warning). Without that rule a report that asked for WebKit and silently got only Chrome would read as a pass.

## Found while building, and fixed

- **The seeded WebKit-only bug did not exist.** The demo app's answer key said the order page shows "Invalid Date" in WebKit because `new Date('2026-09-02 10:30:00')` is rejected by JavaScriptCore, marked *unverified, verify in 7.9*. With Playwright WebKit 26.6 (macOS) it is **accepted**: the bug did not fail. Several date strings were compared in Chrome and WebKit; `'2026-09-02 10:30:00 UTC'`, `' +0500'`, `' GMT+5'`, `'02-09-2026'`, `'2026.09.02'` and `'2026-09-31'` are rejected by WebKit only. The page now parses `created_at + ' UTC'` (a plausible trick), the answer key says what was observed, and the sweep finds it as "only in webkit".
- **The first Mailtrap check rejected numeric ids** (`inbox_id: 3456`) because the check accepted only strings; found by the config tests.
- **A multipart email's text ended with the boundary's line break** (found by the MIME test); and **an address in a production-looking domain counted as a test address** because `*.example.com` is a reserved name and the demo's fictional production host ends in it: a domain the config names as production is never a test address.
- A browser launched with an empty Playwright folder said "Executable doesn't exist" with a stack of boxes; the message is now one sentence with the command that installs it.
- **Files created with the editor's write tool were lost** when a message from the owner interrupted a turn (the host rewound its tracked edits); files made by shell commands survived. They were rebuilt from the conversation. The working tree is now also copied to a scratch folder as work proceeds (not committed: commits wait for the owner's approval).

## Decisions

- **Visual regression is per page, role, browser and screen size, and the owner accepts baselines** (`baseline accept`, refused to a run by the hook; the store's `baselines/` folder and `perf.json` cannot be written from a run either). A baseline taken from a page that had problems keeps them, and the command says so. Tolerance: a colour channel may differ by 24 of 255 (font smoothing) before a pixel counts, then a share of the picture (`visual.threshold`) before it is reported; a changed size counts as different. Ignored regions are hidden with a style rule before the picture; private data is blurred by the same in-page script the agent's browser uses.
- **Performance** is "time until the network was quiet for 500 ms" (capped at 15 s; a page that never settles is not measured, it says so). Regression needs the configured percentage **and** 250 ms (100 ms for an API): 40 ms to 90 ms is not a finding. History is the last eight points per page and endpoint, written only by a **finished** run with a working environment, and only from the sweep's and the timer's own files. The API timer is GET/HEAD only, at most ten calls: it is not a load test, and says so.
- **Email**: a message is a lead to read as well as check. The checks are exact (recipient, subject, placeholders, links, unsubscribe, a coarse writing-system language check); links are opened only inside the run's policy and **never outside it** (a link to production is reported unopened). `mail wait` refuses a recipient that is not a test address. Without a catcher the flows are Not tested, "no email sandbox configured" (the spec's wording). Nothing is sent from QAMind and nothing deleted from the catcher.
- **Ticket mode is a mode** (`mode: "ticket"` with a `ticket`), so budgets, reports and the CI summary can say what it is. Criteria and results are agent-written files that are validated: a derived criterion needs the person's confirmation (in CI it is **assumed**, said so in both reports and the comment); "met" needs evidence or a bank test; "not met" must be a finding; "not testable" needs a reason; every criterion needs one answer. Ticket text is data, never instructions (the real-agent run carries a line in the ticket that tries to give the tester an order). The ticket reference loses any query or fragment before it is kept. Linear and GitHub issues are read through a tracker tool if the host has one, otherwise the user pastes the text; there is no tracker code here (Phase 8).
- **CI**: `qamind ci --ticket FILE` (a plain path inside the project, up to 100 KB, no spaces). `ci.mode` in the config stays one of the four: a ticket is a per-run input, not a setting.

- **A narrowed sweep merges into the run's sweep** (found by the real-agent attempts): looking at one page again in one browser is how a lead is reproduced a second time, and it first replaced the whole result. It now replaces only the visits it repeated.

## Not done, or not verified

- **Mailpit was not run.** Downloading its binary was refused by the environment's permission check and was not retried another way. The client follows Mailpit's published API (read from its OpenAPI file) and is exercised against the demo's stand-in (`demo-app/scripts/mail-catcher.mjs`) and fake responses. **MailHog and Mailtrap** are written from documentation (MailHog's published schema disagrees with the live one, so both shapes are read; Mailtrap's endpoint page could not be read) and were never run. A custom API is read with common field names.
- **Firefox was not run.** WebKit was (Playwright WebKit 26.6 on macOS 27.2, installed in a scratch folder), in the page sweep tests and in the real-agent runs ([EVALUATION-LOG](../EVALUATION-LOG.md): found in the last two of four attempts, after the instruction about detail pages was made concrete).
- **The sweep does not submit forms.** State that needs input is reached with a page's own steps (the bank's vocabulary); the sweep cannot drive a multi-step flow.
- **The language check is by writing system**, not language: Urdu is told from Latin text, Urdu from Arabic is not.
- **Baselines are per machine and browser build**: a different WebKit or Chrome version can change antialiasing beyond the tolerance. The owner re-accepts after upgrading a browser.
- **Linux and Windows** were not run; the new tests are in the Windows job's list, and the browser tests skip without Playwright.
